# 模型容错与导出配置

## 服务器配置

主模型沿用 DEEPSEEK_BASE_URL、DEEPSEEK_MODEL 和用户在设置页保存的主密钥。
备用接口支持 OpenAI 兼容的 /chat/completions 协议，管理员设置：

- TF_BACKUP_URL_1、TF_BACKUP_MODEL_1：第一个备用服务的基础地址和模型名。
- TF_BACKUP_URL_2、TF_BACKUP_MODEL_2：第二个备用服务的基础地址和模型名。

基础地址需包含服务商要求的 /v1 或兼容前缀，不能包含 /chat/completions。使用可信HTTPS地址。配置后重启后端，用户在“设置 → 备用模型接口”填写自己对应服务的API Key。模型名称必须与服务商实际提供的一致。没有配置备用密钥时，不会自动借用其他用户或服务器的密钥。

用户密钥使用现有 AES-256-GCM 加密，列表只返回掩码。删除、读取均按登录账号隔离。主接口失败后依次尝试用户的备用接口。不要只为同一个故障服务增加同地址密钥；要实现服务故障备援，应使用独立服务商或独立部署。

每个请求的模型调用共用约210秒预算，单次读取超时最多45秒；忙碌时明确提示稍后重试。字段结构校验失败最多修复一次，失败不使用模板伪造成功。并发上限8是单实例限制。

## Nginx

在现有 /api/ 代理 location 中保留实际 proxy_pass，并设置：

```nginx
proxy_connect_timeout 10s;
proxy_read_timeout 240s;
proxy_send_timeout 240s;
```

执行 nginx -t 后再重载。仅修改本地代码不会更新云端，需重新构建、上传后端和前端产物后重启服务。线上须启用HTTPS，生产环境使用独立JWT密钥和加密主密钥；主密钥不可随部署更换。

## 导出

导出前生成轻度润色预览：优化一级标题和文字表达，要求保留需求、数字、评分、限制及所有二级章节。章节变化或篇幅变化过大时拒绝生成结果、保留原文。用户可以调整文件名，再确认下载。自动校验不能替代内容核对；用户可直接下载保留的原文。

## 登录提示

按需求区分未注册邮箱与密码错误。这会让访问者能够判断邮箱是否已注册，因此保留登录限流、统一哈希计算，响应不返回其他账号资料。

回归覆盖：JSON代码围栏、额外字段、嵌套字段缺失、错误字段类型、框架与技巧混用、主接口失败后切换、备用密钥加密与账号隔离、导出章节保留。真实服务商连接需在部署环境填写有效密钥后另行验证。

## 厂商选择

设置页内置 DeepSeek、通义千问（北京）、通义千问（新加坡），不再要求管理员先配置备用地址。千问采用官方OpenAI兼容接口，默认qwen-plus。密钥必须与所选地域一致。保存后设为首选；已有密钥可直接切换，无须再次输入。其余密钥保留作备用，旧DeepSeek密钥兼容迁移时只复制密文。自定义备用1、2仍需管理员配置可信地址。

顶部品牌保持左上，返回按钮放在其下方；弹窗返回按钮保留无障碍名称、视觉只显示小于号。小人右侧常驻“点我优化”气泡。
